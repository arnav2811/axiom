### LO4: Evaluate software quality
- **Evidence:** 28+ tests pass. Architecture documented with 8 ADRs. Quality attributes assessed (correctness, usability, maintainability, portability, data integrity, accessibility). User guide enables external evaluation.
- **Files:** `docs/D6/architecture.md` §6, `docs/D6/d6-report.md` §3.4

### LO5: Reflect on professional practice
- **Evidence:** Individual reflections on TDD adoption, refactoring decisions, and user-centred documentation. Sprint retrospective identifies improvements and future work.
- **Files:** `simulated-and-reconstructed/reflection-drafts/Arnav_D6.md`, `simulated-and-reconstructed/reflection-drafts/Keshav_D6.md`

## Key Skills Developed in D6
1. **Test-Driven Development** — Writing tests before implementation for all new features
2. **Refactoring** — Extracting FactorEditor to improve maintainability (SRP)
3. **User-centred documentation** — Writing for end-users, not developers
4. **Data visualisation** — Evidence-based chart type selection (bar vs pie)
5. **Release management** — Delivering a feature-complete release candidate with quality gates
