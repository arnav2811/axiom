# D5 Learning Outcomes

## Module Learning Outcomes Addressed

### LO1: Apply software engineering principles in a team project
- **Evidence:** Sprint 2 delivered 7 stories with consistent application of Definition of Done. Boundary/partition testing applied systematically to all numeric inputs.
- **Files:** `docs/D5/d5-report.md` §2, `docs/D5/sprint-2-review.md`

### LO2: Use Agile SCRUM methodology
- **Evidence:** Sprint 2 planning, daily stand-ups, sprint review, and retrospective conducted. Burndown chart tracks velocity. Sprint 3 backlog prepared with reprioritised stories.
- **Files:** `docs/D5/d5-report.md` §2.3, `docs/D5/sprint-3-plan.md`, `simulated-and-reconstructed/meeting-minutes/d5-phase-minutes.md`

### LO3: Design, implement, and test software to meet requirements
- **Evidence:** Multi-category recording (TRAVEL extension), household aggregation, constraint-respecting coaching, factor badges — all with acceptance criteria verified by tests. Boundary/partition testing covers equivalence classes and edge values.
- **Files:** `docs/D5/d5-report.md` §3, `docs/D5/sprint-2-review.md`

### LO4: Evaluate software quality
- **Evidence:** 20+ tests with boundary coverage. Definition of Done checklist applied to every story. Code quality retrospective identified ActionPlanner refactoring need.
- **Files:** `docs/D5/d5-report.md` §3, §4

### LO5: Reflect on professional practice
- **Evidence:** Individual reflections on testing approaches, collaboration patterns, and Sprint 3 improvement plans.
- **Files:** `simulated-and-reconstructed/reflection-drafts/Arnav_D5.md`, `simulated-and-reconstructed/reflection-drafts/Keshav_D5.md`

## Key Skills Developed in D5
1. **Boundary value analysis** — Systematic identification of input boundaries and partition classes
2. **Equivalence partitioning** — Grouping inputs into valid/invalid classes for efficient test coverage
3. **Ethical design implementation** — Translating design principles (DP2) into code constraints
4. **Sprint velocity tracking** — Using burndown data to calibrate Sprint 3 capacity
5. **Definition of Done** — Formal checklist-based verification for every delivered story
